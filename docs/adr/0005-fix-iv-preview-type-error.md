# 5. 修正 IV 預覽功能的數據類型錯誤 (TypeError)

- **日期**: 2026-03-16
- **狀態**: 已接受並實施

## 背景 (Context)

在修正了 IV 預覽功能的 CSV 解析錯誤後 (見 ADR-0004)，發現功能仍然失敗，並拋出一個新的 `TypeError`: `ufunc 'isfinite' not supported for the input types`。

這個錯誤表示程式碼嘗試對一個包含非數字（如文字字串）的數據系列(Series)執行只有數字才能進行的操作。

## 根本原因分析 (Root Cause Analysis)

上一個修復方案雖然確保了 `pandas` 能夠正確讀取 CSV 的行列結構，但並未保證所讀取數據的 *類型*。

`pandas` 在讀取時，如果一個欄位中含有任何無法直接識別為數字的髒數據（例如一個空字串 `''`，或是一個儀器回報的錯誤訊息文字），為了數據的完整性，它會將整個欄位（`pd.Series`）的數據類型 (`dtype`) 推斷為 `object`（即文字字串），而不是 `float64` 或 `int64`。

後續的程式碼（例如 `.dropna()` 或是 `pyqtgraph` 的繪圖函式）期望得到數字類型的數據。當它們收到一個 `object` 類型的數據系列時，嘗試對其進行數學運算，便引發了 `TypeError`。

## 決策 (Decision)

為了解決這個問題，我們決定在數據處理流程中增加一個明確的、強制性的「數據類型轉換」步驟。這能消除對 `pandas` 自動類型推斷的依賴，使流程更加健壯。

具體決策如下：
1.  **修改 `trend_chart_window.py`**：在 `_on_mouse_moved` 函式中，緊接著 `pd.read_csv` 之後，增加數據類型轉換的邏輯。
2.  **使用 `pd.to_numeric`**：對所有需要用於繪圖的欄位（`fwd_v_corr`, `fwd_i_corr`, `rev_v_corr`, `rev_i_corr`），呼叫 `pd.to_numeric` 函式進行轉換。
3.  **使用 `errors='coerce'`**：在呼叫 `pd.to_numeric` 時，必須包含 `errors='coerce'` 參數。這個關鍵參數指示 `pandas`：如果遇到任何無法轉換為數字的值，不要拋出錯誤使程式崩潰，而是優雅地將該值替換為 `NaN` (Not a Number)。

這樣一來，經過處理的數據系列，其 `dtype` 可以被保證為數字類型（如 `float64`），而所有髒數據都會變成 `NaN`。後續的 `.dropna()` 函式可以自然地將這些含有 `NaN` 的行清除，確保最終用於繪圖的數據是純淨且類型正確的。

## 影響 (Consequences)

### 正面影響
- **錯誤修正**：徹底解決了 `TypeError` 的問題，讓 IV 曲線預覽功能在面對含有非數字字元的數據時也能正常運作。
- **健壯性大幅提升**：程式碼不再隱性地依賴 `pandas` 的自動類型推斷，對髒數據的抵抗力更強，使整個功能更加穩定可靠。

### 負面影響
- 無。這是一個純粹的錯誤修正與程式健壯性增強，沒有引入任何新的風險或破壞性變更。
