# 8. 防止監控視窗在關閉時被銷毀

- **日期**: 2026-03-16
- **狀態**: 已接受並實施

## 背景 (Context)

使用者回報了一個問題：在量測開始後，如果不慎關閉了「實時 IV 曲線戰情室」(`IVMonitorWindow`) 或「長期穩定性與壽命分析中心」(`TrendChartWindow`)，這兩個視窗便無法再次被開啟。

根本原因在於，當使用者點擊視窗的「X」按鈕時，Qt 框架的預設行為是將該視窗物件**銷毀 (Destroy)**。由於程式的主邏輯 (`main_window.py`) 只在啟動時或掃描開始時建立這些視窗的實例，一旦被銷毀，就沒有內建的機制可以手動將它們重新顯示出來。

## 決策 (Decision)

為了提升使用者體驗的容錯率與流暢性，我們決定改變視窗的預設關閉行為，從「銷毀」改為「隱藏」。

這確保了每個監控視窗的實例在應用程式的生命週期中是**單一且持久的 (Singleton-like)**。

具體實施步驟如下：

1.  **修改目標視窗**:
    -   `gui/iv_monitor_window.py`
    -   `gui/trend_chart_window.py`

2.  **覆寫 `closeEvent`**:
    -   在這兩個視窗的類別中，我們覆寫 (override) 了 `closeEvent(self, event)` 方法。

3.  **實作新邏輯**:
    -   在被覆寫的 `closeEvent` 方法中，我們執行了兩行關鍵程式碼：
        -   `self.hide()`: 將視窗從螢幕上隱藏，但其物件本身、包含的所有子元件以及數據狀態都完整地保留在記憶體中。
        -   `event.ignore()`: 通知 Qt 框架，我們已經處理了這個關閉事件，請它不要再執行後續的預設銷毀動作。

4.  **主視窗邏輯不變**:
    -   `main_window.py` 中現有的 `self.iv_monitor.show()` 和 `self.trend_chart.show()` 呼叫無需修改。它們現在可以完美地作用於一個已經存在但被隱藏的視窗實例，使其重新可見。

## 影響 (Consequences)

### 正面影響
- **使用者體驗提升**: 使用者現在可以隨意關閉（隱藏）和重新顯示監控視窗，而不會遺失任何視窗或其內容，操作更加靈活且具備容錯能力。
- **狀態保持**: 由於視窗實例得以保留，其內部的所有狀態（如已繪製的圖表、縮放等級、捲動位置等）在視窗被隱藏和重新顯示之間都會被完整保存。
- **效能提升**: 避免了重複建立和銷毀複雜視窗物件可能帶來的微小效能開銷。

### 負面影響
- **記憶體佔用**: 被隱藏的視窗會持續佔用記憶體。然而，對於一個桌面應用程式來說，這兩個監控視窗所佔用的記憶體是可預期且可接受的，此影響微乎其微。
