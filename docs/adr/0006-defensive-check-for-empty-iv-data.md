# 6. 為 IV 預覽功能增加對空數據的防禦性檢查

- **日期**: 2026-03-16
- **狀態**: 已接受並實施

## 背景 (Context)

在修正了 IV 預覽功能的 CSV 解析錯誤 (ADR-0004) 和數據類型錯誤 (ADR-0005) 後，功能在多數情況下已可運作。然而，在特定邊界條件下，仍然會拋出一個未處理的異常，日誌僅顯示為 `: 0`，導致功能再次失敗。

這個問題的出現，表明此功能的錯誤處理和防禦性設計仍有不足，未能覆蓋所有可能的使用情境。

## 根本原因分析 (Root Cause Analysis)

經過深入的追蹤與審查，確認此錯誤的根本原因在於：**程式未能正確處理一個內容完全為空或不含任何有效數據的 CSV 檔案**。

失敗的流程如下：
1.  使用者滑鼠懸停在一個數據點上，該點對應的 `..._IV curve.csv` 檔案雖然存在，但可能因為某些原因（如量測中斷）而未寫入任何有效的數據行。
2.  `trend_chart_window.py` 中的 `pd.read_csv` 函式在使用了 `comment='#'`, `header=None`, `names=...`, `on_bad_lines='skip'` 這些強大的參數後，正確地處理了這個檔案，沒有拋出解析錯誤，而是返回了一個**空的 DataFrame** (一個沒有任何行和列的數據集)。
3.  然而，後續的程式碼**沒有檢查**這個 DataFrame 是否為空，而是直接假設它有數據，並嘗試從中存取欄位，例如 `df['fwd_v_corr']`。
4.  對一個空的 DataFrame 存取一個不存在的欄位，會引發一個 `KeyError`。這個未被更具體地處理的 `KeyError` 就是造成日誌中出現奇怪錯誤訊息的來源。

## 決策 (Decision)

為了徹底解決此問題並使功能達到生產級的穩定性，我們決定在數據處理流程中增加一個最終的、關鍵的「**防禦性檢查**」。

具體決策如下：
1.  **修改 `trend_chart_window.py`**：在 `_on_mouse_moved` 函式中，緊接在 `pd.read_csv(...)` 的呼叫之後。
2.  **增加空數據集檢查**：加入一行 `if df.empty:` 判斷。
3.  **提前返回**：如果 DataFrame 為空，則記錄一條警告日誌，隱藏預覽視窗，並**立即 `return`**，以終止後續所有試圖對空數據集進行的操作。

這個檢查確保了只有在確定已成功讀取到有效數據時，程式才會繼續執行數據轉換和繪圖的流程。

## 影響 (Consequences)

### 正面影響
- **徹底的錯誤修正**：此防禦性檢查補全了數據處理鏈中最後一個缺口，徹底解決了 IV 預覽功能面對各種無效檔案時可能崩潰的問題。
- **健壯性與穩定性**：此功能現在能夠優雅地處理格式錯誤、類型錯誤以及無數據這三種主要的異常情況，達到了預期的穩定性要求，避免了後續可能出現的同類問題。

### 負面影響
- 無。這是一個純粹的健壯性增強，使程式的行為更加可預測和安全。
