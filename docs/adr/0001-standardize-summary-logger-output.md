# 1. 標準化 Summary Logger 的輸出格式

- **日期**: 2026-03-16
- **狀態**: 已接受並實施

## 背景 (Context)

`core/summary_logger.py` 模組負責將每次測量的分析結果匯總到一個 CSV 檔案中 (`Summary_report.csv`)。

在本次修改之前，該模組會根據傳入數據的字典鍵動態生成 CSV 的標頭。這導致了幾個問題：
1.  **順序不固定**：欄位的順序可能會因程式執行緒或字典實現的細微差異而改變。
2.  **格式不符**：輸出的單層標頭格式與專案中提供的模板 `data/Summary_report _template.csv` 所定義的雙層標頭格式不符。
3.  **可讀性差**：不一致的格式增加了手動或自動化工具讀取和分析數據的難度。

為了數據處理的穩定性和可預測性，必須有一個統一的輸出格式。

## 決策 (Decision)

我們決定重構 `core/summary_logger.py`，使其嚴格遵循 `data/Summary_report _template.csv` 的格式。

具體措施如下：
1.  **硬式編碼標頭**：在程式碼中定義三個常量列表：
    - `HEADER_ROW_1`：儲存模板的第一層分類標頭。
    - `HEADER_ROW_2`：儲存模板的第二層參數標頭。
    - `DATA_KEYS`：儲存與 `HEADER_ROW_2` 完全對應的數據字典鍵，此列表定義了數據的寫入順序。
2.  **修改寫入邏輯**：
    - 在創建新的報告檔案時，嚴格按照 `HEADER_ROW_1` 和 `HEADER_ROW_2` 的順序寫入標頭。
    - 在寫入每一行數據時，遍歷 `DATA_KEYS` 列表，從傳入的數據字典中安全地 (`.get()`) 獲取數值，並依序寫入。這確保了數據與標頭的完美對齊。
3.  **檔案路徑調整**：將原本為每個 "Device" 建立一個報告的邏輯，修改為每個 "Project" 建立一個總報告，這更符合模板檔案作為專案總結的意圖。

## 影響 (Consequences)

### 正面影響
- **格式統一**：所有新生成的 `Summary_report.csv` 都將擁有完全相同的欄位結構和順序。
- **可靠性提升**：自動化腳本可以依賴固定的欄位順序來解析數據，無需擔心格式變動。
- **可維護性**：將格式定義集中在程式碼頂部的常量中，使得未來的格式調整更加清晰和方便。

### 負面影響
- **與舊檔案不兼容**：此變更只對新生成的報告有效。在此之前生成的報告將保留其舊的、不固定的格式。如果需要處理歷史數據，可能需要額外的腳本來進行清洗和格式化。
