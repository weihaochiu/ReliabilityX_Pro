# 2. 新增專用的「關閉程式」按鈕

- **日期**: 2026-03-16
- **狀態**: 已接受並實施

## 背景 (Context)

在解決了「關閉視窗時未釋放硬體資源」的問題後 (見 `MainWindow.closeEvent` 的修正)，應用程式的關閉流程已變得安全。然而，從使用者體驗 (UX) 的角度來看，僅依賴作業系統視窗框架的 'X' 按鈕來關閉一個儀器控制軟體，可能不夠直覺或清晰。使用者可能不確定 'X' 按鈕是否會執行必要的安全關閉程序。

## 決策 (Decision)

為了提升操作的直覺性和使用者的信賴感，我們決定在主操作介面上新增一個專用的「關閉程式」按鈕。

具體實施方式如下：

1.  **位置**：在 `gui/widgets/control_panel.py` 的「系統管理」群組框中新增一個 `QPushButton`。這讓退出應用的操作與「設定」、「日誌」等系統級操作放在一起，符合邏輯分組。
2.  **通訊機制**：採用 PyQt 的信號/槽 (Signal/Slot) 機制來解耦 UI 與主視窗邏輯。
    - `ControlPanel` 增加一個 `exit_requested` 信號。當使用者點擊「關閉程式」按鈕時，此信號被發射。
    - `MainWindow` 捕獲此 `exit_requested` 信號，並將其連接到 `MainWindow` 自身的 `self.close()` 方法。
3.  **複用關閉邏輯**：呼叫 `self.close()` 方法會標準地觸發 `MainWindow` 的 `closeEvent`。這意味著，無論使用者是點擊這個新按鈕，還是點擊視窗的 'X' 按鈕，都會執行完全相同的安全關閉代碼 (停止量測引擎、關閉硬體連線等)，避免了代碼重複並保證了行為的一致性。

## 影響 (Consequences)

### 正面影響
- **提升使用者體驗**：提供了一個清晰、明確的退出應用程式的入口點。
- **增強信賴感**：使用者可以確信點擊此按鈕會執行安全的關閉程序。
- **代碼優雅**：通過複用 `closeEvent`，此功能在不增加複雜性的前提下得以實現，保持了代碼的簡潔和可維護性。

### 負面影響
- 無明顯的負面影響。此變更僅為 UI 層面的增強，未改動核心邏輯，風險極低。
