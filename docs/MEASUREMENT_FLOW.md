# 線阻、極性與正式太陽能電池量測流程

更新：2026-09-21，ADR-0062。適用受光太陽能電池，不是鋰電池等儲能電池。

## 現場回報後的查詢修正與錯誤說明（ADR-0063）

15:38–15:41 的新日誌顯示：Relay 控制器回報 3/57 已開啟，隨後 SMU 在電流設定查詢
`:SOUR:CURR:LEV?` 逾時，尚未發出 ON / READ?；清理再確認 OFF 與 Relay 全關。
所以當時「夾子接上或分開都失敗」不是一次有效的開路測試。

已改為手冊明列 `:SOUR:CURR?` / `:SOUR:VOLT?`，不改寫入值，也不跳過讀回比對。
若仍逾時，程式會停止並提供原始指令；不能假定新拼法已在實機驗收。

新版視窗分成中文原因、停止步驟、進度／安全證據、建議處理、可展開的技術詳細與
「複製診斷資料」。其中：

- 「尚未送出 ON」：未開始通電量測，應查設定／通訊；接夾子不能排除查詢逾時。
- 「已取得 V/I、可能開路」：若故意分開兩夾，拒絕校正是預期結果；要做線阻校正時，
  確認 OUTPUT OFF、移除電池後才互夾重測。
- 「SMU OFF／Relay 全關未確認」：先在面板確認或手動關閉輸出，不能直接換線。
- 「Relay 控制器狀態已確認」：僅代表邏輯 mask；如果仍看不到接點／指示燈動作，

- Chamber 開埠失敗與有開埠但無 telemetry 分開解釋。這份日誌設定 COM1，但枚舉的
  USB-RS485 是 COM8；由操作者確認實際埠與站號，程式不自動改設定。這不是上述線阻逾時的原因。

設定頁既有同步硬體操作未在此版整批搬移 worker；新增的報告不會追加硬體查詢。
線阻與極性請求仍經 queued worker 執行。新增 Python 模組由既有 PyInstaller imports
收集，不需修改 build_and_deploy.py 或新增資產打包參數。

## 1. 先做線路電阻校正（不接電池）

先依現場安全程序確認 SMU output OFF，將對應 SMU+ / SMU− 的兩個鱷魚夾互夾短路；
不要讓太陽能電池留在此校正回路。Relay 編號採十進位 0–63，3/57 即實體 Relay 3 與 57。

1. 設定頁發出 queued request，量測 worker 檢查硬體就緒、未在執行其他量測、pair 合法。
2. 讀回確認 SMU OFF；Relay 全關並讀回零 mask；打開選定 pair，讀回完整 mask 必須只含這兩路。
3. 設定固定電流 +10 mA、限壓 1.5 V；讀回確認模式、電流與限壓；開啟並確認輸出。
4. 等待 0.5 s，讀取實測 V/I 及限壓旗標，全部記錄於 `[R-line SAMPLE]` / `[SMU VERIFIED]`。
5. 限壓或未知狀態、非有限數值、電壓 >=1.485 V、實測電流不在 +10 mA ±1%：拒絕。
   否則以 `R = abs(V_measured / I_measured)` 計算，不能拿設定的 10 mA 當分母。
6. 確認 SMU OFF 與 Relay 全關。清理任一步未確認，仍視為失敗，不回傳可儲存校正值。
7. GUI 儲存 v2 校正 JSON 成功後，再寫入線阻歷程並通知成功。紀錄保留 V/I、設定值、限壓、
   compliance、時間、操作者、元件與 pair。GUI 的 JSON 寫入失敗不再假報成功。

兩夾分開且沒有其他回路時，不應接受約 149 Ω 或 0 Ω 作為校正。舊程式的 1.499 V / 設定
10 mA 就會變成 149.9 Ω，卻沒有檢查真實電流；這是已重現的軟體缺陷，不是現場接線故障的證明。

**更新後所有舊版線阻仍保留，但需重新量測，不能直接拿來校正正式數據。**

## 2. 接上受光太陽能電池，正式量測前強制確認極性

完成線阻校正並確認 OFF 後，再依現場安全程序把夾子接至電池正負端。
按開始掃描之後，每顆通道、每次排程到期的正逆掃之前都必須重新通過以下檢查；
之前手動「即時連線測試」成功不會免除這一步。

1. 驗證通道的 Relay、電壓範圍、步階、限流、面積及排程參數。
2. 載入該 pair 的線阻，驗證 v2 原始證據、V/I 與保存阻值一致、未過期；不合格在切換前停止。
3. 確認 SMU OFF → Relay all-off → 選定 pair → readall 只含該 pair → 等待 0.3 s。
4. 設定 0 V，限流取「通道設定、全域上限、0.1 A」中的最小值，確認設定與輸出，等待 0.1 s。
5. 取得實測 V/I 與限流旗標，使用扣掉 offset 的**帶正負號電流**判斷：

| 條件 | 結果／處理 |
|---|---|
| 有限值、未限流、實測電壓在 ±10 mV 內，且 I_corr < −10 µA | 極性正常，允許正式掃描 |
| I_corr > +10 µA | 可能反接；停止，不執行正逆掃 |
| −10 µA ≤ I_corr ≤ +10 µA | 開路／無光／弱光／訊號太小，無法確定；停止 |
| 限流、未知旗標、非有限值或無法達到近 0 V | 極性未確認；停止 |

異常會記錄 `[POLARITY]` 原始證據，執行 OFF / all-off 清理，停止全域排程，不進下一顆。
這不是儲能電池的安全極性測試；也不能單憑電流正負判斷所有電氣接線故障。
10 µA、10 mV 與 0.1 A 是目前保守門檻，弱光、小面積或較高 Isc 元件可能被阻擋。

## 3. 正式正掃與逆掃

1. 極性通過後先 OFF，建立 `V_start → V_stop` 的正掃點列。最後一步可縮短，絕不超過 V_stop。
2. 設定並讀回確認電壓源／固定模式／通道限流；開啟且確認輸出。
3. 每一點設定電壓並讀回，等待通道 delay_time，讀取實測 V/I 與限流狀態。
   通訊失敗、限流或無效數字會中止本次量測，不能補 0 或當成正常曲線。
4. 每點保留 `v_src`（設定值）、`v_msd`（實測值）、`i_msd`（帶符號實測值），先做
   `I_corr = I_measured − offset_current`，再做 `V_corr = V_measured − I_corr × R_line`。
   不可先對電流取絕對值，否則發電區的線阻補償方向會錯。
5. 正掃結束後，以相同點列逆序做 `V_stop → V_start` 逆掃；兩方向間保持輸出連續。
6. 逆掃完成即確認 OFF，再分析及存檔。Raw 分析／畫面／CSV 使用實測電壓；只有舊資料
   沒有 `v_msd` 才 fallback 至 `v_src`。Corr 使用校正後 V/I。
7. 分別計算正逆掃 Raw/Corr 的 Voc、Isc、Jsc、FF、PCE、Rs/Rsh、Pmpp 等。
   寫入 IV curve CSV、Summary report；曲線檔含極性證據、線阻驗證版本與 Raw 電壓來源。
8. 再次確認 SMU OFF、Relay all-off 後，才發送「通道量測完成」、更新卡片與成功計數。
   分析、存檔或清理失敗均不算完成；若檔案先存好才清理失敗，檔案可能存在，必須看失敗 log。
9. 排程間隔仍以原 scheduled_due + interval 為基準；使用者要求停止時，完成當前正逆掃後停。
   極性或硬體故障則中止當前嘗試及後續通道。新增讀回會增加實際每點通訊時間。

## 4. 推送前驗證與實機驗收界線

自動化驗證全部是離線 mock：禁止 VISA/Serial/Socket 連線及真正的 SMU ON / Relay 動作。
涵蓋完整排程、GUI、檔案、線阻開路／限壓／清理、極性與正式掃描故障注入。

在測試機由操作者執行（不由開發機自動控制）：

1. 更新後確認啟動路徑和版本；保留原始校正與日誌備份。
2. 不接電池，3/57 兩夾分開：應量測失敗，校正紀錄不更新；保存 TX/RX、V/I、compliance。
3. 按安全程序確認 OFF 後互夾：應量到合理且可重複的低阻，不預設一定為 0 Ω。
4. 接受光太陽能電池，確認正接、反接及低光／斷路各案例的判斷；換線前先確認 OFF。
5. 正常正逆掃後比對畫面、IV curve、Summary 的 Raw/Corr；故障不能寫成成功、不能進下一顆。
6. 如果夾子分開仍通過新版 V/I 檢查，需實測配線與 Relay 接點隔離；readall 只證明控制器
   回報狀態，不能排除焊接短路、接點黏住或共用線。不要自行放寬 guardrail 來通過測試。

## 5. 建置與非 active 路徑

無新套件、UI 資產或 `--add-data` 需求；不改 build/deploy 行為。既有建置入口仍為：

```powershell
python build_and_deploy.py
```

`build_and_deploy.py` 的既有 `compile_ui.py` 與 PyInstaller import 收集即涵蓋本次變更，
無須新增打包程式碼片段。未連線的 Phase-1 DiagnosticsService 線阻舊方法已停用，
正式入口是 MeasureEngine queued diagnostics；勿把 scaffold 重新接回 GUI。
